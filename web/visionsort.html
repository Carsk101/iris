the algorithm

Most sorting algorithms know nothing about their input. They compare and swap blindly — treating every array as equally unknown.

VisionSort profiles before it sorts. A single forward pass measures entropy, samples disorder, identifies anchors, and maintains a running_surprise signal that updates with every element. When the pass completes, it knows what it's looking at. Then it sorts.

iris inherits this pass entirely. The actual sorting never runs — only the perception stage does.

// the signal running_surprise: f64 // 0.0 → completely predictable // 1.0 → maximally chaotic // updated per element running_surprise = running_surprise * 0.995 + surprise * 0.005

three signals

"iris does not sort. it only perceives. these are the three outputs it takes from visionsort's profiling pass."

i

running_surprise → stage gating

When surprise stays low, the data is patterned. iris opens its expensive stages — resonance extraction, stride grammar, the prediction graph. When surprise is high it routes directly to the codec. The signal itself decides. Nothing is tuned by hand.

ii

LCG disorder sampler → block fingerprints

VisionSort samples random index pairs via an LCG to estimate disorder. iris intercepts that same LCG stream. Each sampled pair, hashed and accumulated, builds a 64-bit SimHash fingerprint per block. The fingerprints feed the prediction graph and cost nothing extra — the LCG was running anyway.

iii

phase 2 anchors → resonance seeds

VisionSort segments the array using anchor elements during its second phase. iris reads the anchor spacing as candidate lag values for resonance detection. On nearly-sorted integer data, the anchors repeat at the integer stride — iris finds the dominant period on the first attempt rather than scanning all 64 lags blindly.

nearsorted.bin

4,000,000 bytes · 1M u32 integers · 200 random swaps

The profiling pass runs. running_surprise holds near 0.02. Autocorrelation peaks at lag=4 with strength 1.000 — one integer width. Stage gates open fully.

Resonance extraction fires at lag=4. The residual is data[i] wrapping_sub data[i-4] for every byte — six unique values across 3,999,996 bytes, mostly 0x00 and 0x01.

That residual goes to bzip2. BWT sorts the near-constant stream into long identical runs. MTF collapses them to near-zero symbols. Output: 9,857 bytes.

Final ratio: 405x.
zstd -19 gets 171x. bzip2 alone gets 247x.

shared principle

VisionSort's core constraint is self-imposed: pay for one read, use it for everything. No second pass, no backward seeks. The entire sorting strategy commits after a single forward traversal.

iris applies the same constraint. Its profiling pass builds the context table, computes autocorrelation at 64 lags, accumulates SimHash fingerprints, and tracks running_surprise — all in one forward read. Every stage downstream uses this profile.

Perception is cheap and complete before any action begins. This is what VisionSort taught, and what iris inherited.

how it works

the architecture

iris treats data compression as a perception problem. rather than applying a single algorithm to everything, it reads the dataset once, understands its structural profile, and routes the data through the stage best equipped to eliminate its specific redundancy.

profile & route

a single read-only pass calculates byte entropy, autocorrelation at multiple lags, and block fingerprints. the system then routes the data dynamically.

structured text like csv decomposes via a column grammar into individually typed streams. binary data with a dominant period falls into wrapping i8 residuals via resonance.

// example of dynamic grammar routing
struct colspec {
    enc:        u8,
    pfx:        vec<u8>,
    sfx:        vec<u8>,
    data:       vec<u8>,
}

prediction graph

standard compressors like lz77 are constrained by a small sliding window. iris removes this limitation by finding similar blocks anywhere in the file via minhash fingerprints.

highly correlated structural blocks are matched regardless of physical distance and stored efficiently as xor deltas.

hardware encoding

for data that remains highly entropic (>0.80), the bytes are context-packed into frames and pushed to an nvidia gpu. the system negotiates av1_nvenc or hevc_nvenc.

if no suitable gpu is found, it falls back elegantly to the cpu using lossless libx264. near-constant residuals (<0.15) bypass the gpu entirely and are packed via pure bwt+mtf.
